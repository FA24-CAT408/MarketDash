## Design Context

### Users

The primary user is CrazyMarket's developer working alone at a desktop. The
interface is a private development tool for driving and inspecting a player
locomotion state model, not a player-facing screen or a stakeholder demo.

### Brand Personality

Calm, tactile, and gentle. The tool should feel like a quiet physical workbench:
direct and trustworthy without looking harsh, dense, or clinical.

### Aesthetic Direction

Use a warm-light, low-stimulation interface with softly tinted neutral surfaces,
clear state labels, and controls that feel pressable. Prefer a restrained
workbench or field-notebook character over game-themed chrome, neon developer
dashboards, generic cards, glass effects, or decorative animation.

### Design Principles

- Make the active state, latest transition, and rejection reason obvious at a
  glance.
- Keep every control close to the state it affects and label it in CrazyMarket's
  domain language.
- Use tactile feedback through shape, contrast, and pressed states rather than
  visual noise or motion.
- Surface the full relevant state after every action without requiring developer
  tools or raw JSON inspection.
- Favor calm hierarchy and generous breathing room while keeping the entire
  transition workbench useful on a desktop screen.
