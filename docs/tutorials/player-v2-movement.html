01 / LOOP

One motor step, end to end

Input is captured continuously, but movement decisions happen during KCC’s velocity callback. A one-shot jump remains queued until KCC finishes the whole step.

02 / RULES

What the movement rules actually do

There are only three locomotion modes. Responsiveness comes from timers and output policies, not extra states.

Grounded movement

Normalized camera-relative intent is multiplied by StableMoveSpeed. KCC projects both current and target velocity onto the ground tangent, then eases toward the target with exponential sharpness.

Groundedinput × 10Ground tangent

Air control and falling

Air input accelerates toward an 8-unit target without adding speed once already at the cap. A steep-contact guard prevents air input from becoming wall-climbing velocity. Falling uses doubled gravity.

Airborneaccel 60Capped planar

Jump, buffer, and coyote

A base jump is legal while grounded or during the 0.2-second coyote window. A press is remembered for 0.15 seconds. On acceptance, KCC force-ungrounds and replaces the vertical component with jump speed.

Groundedpress / coyoteAirborne

Double jump is composition

If the base jump cannot fire, the machine asks participating ability components. DoubleJumpAbility consumes one extra jump and resets only after stable landing. A buffered press does not later trigger the double jump; it requires that frame’s press.

Airborneability consumes 1Air jump

Control blocking

Blockers are keyed by source, so overlapping systems cannot accidentally unblock one another. Any blocker clears queued jump state and disables planar control while preserving vertical motion. Re-enabling movement removes only the MovementEnabled source.

Any modeblock sourceDisabled

Teleport and reset

A validated teleport is queued into the next machine step. That step ignores input, clears coyote and jump buffer, cancels abilities, and asks the controller to apply position and rotation after KCC finishes. Test Campus reset also zeroes velocity.

Queuednext stepFinite + controllable
Important caveat: jump release is not variable jump height

jumpHeld is carried through the intent contract, but no current rule changes vertical velocity when it becomes false. It is an extension seam, not shipped short-hop behavior.

03 / SEAMS

Three owners, one direction of travel

The useful mental model is a decision boundary, not a collection of MonoBehaviours.

Decides

PlayerLocomotionMachine

Owns modes, coyote and buffer timers, profile/modifier resolution, ability evaluation, snapshots, and presentation state.

Executes

PlayerControllerV2

Owns Unity lifecycle, input subscription, camera-space conversion, KCC observations, motor-safe velocity, collision filtering, and teleport application.

Observes

PlayerAnimationPresenter

Reads the published state before Animator evaluation. It never decides gameplay: grounded speed drives running; airborne drives jumping; revision flags trigger particles once.
