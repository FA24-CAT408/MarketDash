Player V2 layer map

Start here when deciding where a change belongs or where a defect could have entered the movement pipeline.

LayerOwnsLook here when…
InputReaderDevice action callbacksPress, release, or move values never arrive.
PlayerControllerV2 input fieldsrawMove, jumpQueued, jumpHeldAn event arrives but intent is stale, duplicated, or consumed too soon.
PlayerControllerV2 adapterCamera space, KCC observations, applying outputDirection, slope response, rotation, or final velocity is wrong.
PlayerLocomotionMachineModes and gameplay rulesJump eligibility, coyote time, buffering, blocking, modifiers, or teleport policy is wrong.
PlayerProfileAuthored and runtime tuningThe rule is correct but its speed, acceleration, gravity, drag, or timing feels wrong.
PlayerAbilityComponentOptional composed behaviorA feature should be added or removed without expanding the locomotion machine.
KinematicCharacterMotorCollision, grounding, motor lifecycleV2 emits correct output but collision-resolved motion is still wrong.
PlayerAnimationPresenterAnimator booleans from presentation stateMotion is correct but animation is not.
Debugging order: input event → cached intent → body observation → locomotion output → applied velocity → motor collision result → presentation.

Stable contracts

PlayerIntent says what the player asked for. PlayerBodyObservation says what KCC currently knows. LocomotionOutput says what policy wants the adapter to apply. PlayerSnapshot and PlayerPresentationState expose results to tools and visuals.
